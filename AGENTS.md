# Codex: подключение общих правил

Перед работой прочитай [CLAUDE.md](CLAUDE.md) целиком и соблюдай его как общие инструкции проекта. Это единственный источник правил разработки для Claude Code и Codex; новые общие правила и изменения существующих вноси туда.

Процедуры навыков хранятся только в `.claude/skills/<name>/SKILL.md`. Файлы в `.agents/skills` подключают их к Codex и не должны содержать копии процедур. При использовании навыка прочитай его исходный файл целиком; относительные пути внутри него разрешай относительно исходного файла, а пути вида `app/`, `shared/`, `.claude/` — относительно корня проекта.

## Особенности Codex

- Ссылки на `/git-commit`, `/git-push` и `/ui-component` в общих инструкциях означают соответствующий навык; в Codex его можно вызвать как `$git-commit`, `$git-push` или `$ui-component`.
- `Agent`, `subagent_type`, Haiku и YAML-настройки в `.claude/agents` относятся к Claude Code. В Codex выполняй соответствующий сценарий в основной сессии, прочитав также `.claude/agents/git-committer.md` или `.claude/agents/git-pusher.md`, когда на него ссылается навык. Сохраняй разделение планирования и выполнения, подтверждение плана коммитов и все ограничения исходного сценария. Если разработчик явно просит делегирование, используй доступные средства Codex.
- `.claude/settings.json` и `.claude/hooks/format.mjs` настраивают Claude Code и автоматически в Codex не запускаются. После изменения поддерживаемых исходных файлов выполняй локальный ESLint с `--fix --no-warn-ignored` для изменённых файлов, затем Prettier для файлов, которые он поддерживает и которые не игнорируются. Markdown исключён существующим `.prettierignore`. Не форматируй весь проект ради отдельной правки.
- Настройки Claude Code сохраняй в `.claude/settings.json`; особенности подключения Codex — здесь и в коротких файлах `.agents/skills`. Общие правила и процедуры туда не переноси.
