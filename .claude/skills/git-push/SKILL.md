# Push в resume-site client

Основная сессия готовит push и задаёт вопросы. Push и разбор ошибок хука делает субагент `git-pusher` (Haiku). Субагент не умеет спрашивать разработчика, поэтому все вопросы — здесь.

## Жёсткие правила

- Никаких `--force`, `--force-with-lease`, `--no-verify`, `rebase`, `reset`, `--amend` и удаления веток, если разработчик сам об этом не попросил.
- Не трогать незакоммиченные правки разработчика без его решения.
- Исправления после ошибок хука не коммитить и не пушить повторно: показать и остановиться. Закоммитить их — через скилл git-commit, когда разработчик попросит.

## 1. Подготовка

1. Посмотреть состояние: `git status --short`, `git branch -vv`, `git remote -v`.
2. Нет remote или у ветки нет upstream — сообщить и спросить адрес remote и ветку. Remote добавлять (`git remote add`) только после ответа. Первый push — `git push -u <remote> <ветка>`, дальше — `git push`.
3. Коммиты, которые уйдут: `git log --oneline HEAD --not --remotes`. Пусто — сказать, что пушить нечего, и закончить.
4. Есть незакоммиченные правки — pre-push проверяет рабочую копию, и они могут уронить проверки. Спросить заранее: закоммитить их (через git-commit), убрать в stash на время push или остановиться.

## 2. Push

1. Запустить `git-pusher` (`subagent_type: git-pusher`) и передать ему команду push и, если разработчик выбрал stash, список файлов для stash.
2. Push прошёл — к итогу.
3. Push упал — показать разбор субагента:
   - ошибка в незакоммиченных правках — спросить, что с ними делать;
   - простая ошибка в закоммиченном коде, которую субагент исправил, — показать diff и остановиться;
   - сложная ошибка — показать шаг, ошибку и варианты и спросить разработчика;
   - ошибка не от хука (сеть, права, ветка разошлась с remote) — показать и спросить. Никакого force.

## 3. Итог

Показать, что ушло (`git log --oneline` по отправленному диапазону) и `git status --short`.
