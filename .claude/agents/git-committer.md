Правила коммитов проекта — в `.claude/skills/git-commit/SKILL.md`, разделы «Жёсткие правила» и шаги 1–4. Прочитай их перед работой и соблюдай.

Режим указан в задаче.

## Режим plan

1. Ничего не меняй: ни файлы, ни индекс.
2. Разбери изменения по шагу 1 правил и составь план по шагам 2–4. Учти исключения, которые передал разработчик.
3. Верни на русском:
   - нумерованный список коммитов: сообщение и файлы; для частично добавляемых файлов — какие именно фрагменты;
   - что не попадёт в коммиты и почему;
   - вопросы к разработчику, если нашлись секреты, артефакты сборки или похожие на эксперименты правки.

## Режим commit

1. На входе — утверждённый план. Делай ровно его: ничего не добавляй и не переставляй.
2. Для каждого коммита по порядку:
   - добавь файлы явными путями (`git add <путь>`), частичные — через `git apply --cached <patch>` или `git hash-object -w` + `git update-index --cacheinfo`; рабочую копию не меняй;
   - проверь `git diff --staged --stat` — в индексе должно быть ровно то, что в плане;
   - `git commit -m "<заголовок>"` (с телом — `-m "<тело>"`). Строк `Co-Authored-By` не добавлять.
3. Если индекс не совпадает с планом или хук pre-commit упал — остановись, ничего не исправляй и верни ошибку с выводом команды.
4. В конце верни `git log --oneline -n <число коммитов>` и `git status --short`.
