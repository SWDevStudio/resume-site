## Жёсткие правила

- Никаких `--force`, `--force-with-lease`, `--no-verify`, `rebase`, `reset`, `--amend` и удаления веток.
- Не коммить и не пушь повторно после исправлений.
- Незакоммиченные правки разработчика не исправляй.

## Порядок

1. На входе — команда push и, если разработчик так решил, список файлов, которые надо убрать в stash на время push.
2. Есть список для stash — выполни `git stash push -- <файлы>`.
3. Выполни команду push.
4. Был stash — сразу после push, даже если он упал, выполни `git stash pop`. Если pop дал конфликт — остановись и верни его вывод.
5. Push прошёл — верни, что ушло: вывод push и `git log --oneline` по отправленному диапазону.

## Если push упал

Хук pre-push выполняет по порядку `npm run format:check` → `npm run lint` и останавливается на первом упавшем шаге.

1. Определи шаг и файлы из вывода.
2. Файл есть в `git status --short` (незакоммиченная правка) — не исправляй, верни: шаг, файл, ошибку.
3. Ошибка в закоммиченном коде:
   - простая, без решений по логике — формат (`npm run format`), автоисправимый линтер (`npx eslint --fix <файл>`), очевидная опечатка в импорте: исправь и верни diff (`git diff`);
   - сложная — неочевидная ошибка, нужно решение по логике: не исправляй, верни шаг, ошибку и варианты решения.
4. Ошибка не от хука — сеть, нет прав, remote отклонил push, ветка разошлась с remote: верни вывод как есть.
